# E10 Missing levers
## Behaviour
A pillar's lever socket can start empty (lever flag 1 clear, "pilar levier" object hidden). When Jack carries a lever (item 10, I10) and stands within 2 m of the empty socket the socket shows prompt id 0xe ("insert lever"). Activating it (flag 0x8000): the door loop sets `player+0x3cd0 = 1` and `player+0x3d28 = socket` (starts the insert animation `H_TRACK_joueur`), waits until `player+0x3cd0` returns to 0, then mounts the lever (flag 1 set, the socket shown, collision/prompt switch to the crank prompt), clears `G+0x4588` and releases any weapon cell still holding item 10 (`G+0x3348/0x3394/0x33e0` compare against 10). A door with a mounted lever but no operator shows prompt 9 instead. Mounted levers are remembered through the same persistence id (`this[0xa5+i]`, ids 1..2) so a lever inserted before a checkpoint stays.
Level scripts can also test "player has lever" (`TrigTest_Levier@0x469940`, invertible) to open a plain door when the lever is brought [C].
## Code
`InteractiveDoor_loop@0x876330` (first pillar-loop branch, `fn@0x415a60(lever,1)==0`), `InteractiveDoor_init` (pillar setup: lever positioned 1.28 along the pillar's up and -0.5 along its axis), `TrigTest_Levier@0x469940`, `fn@0x48df40` (per-pillar helper assignment, lever flag 1/2).
## Numbers
prompt radius 2 m, prompt ids 0xe / 9, lever socket offset 1.28 / -0.5 [C].
## Rust
`companions::{HeldItems::insert_lever, trig_test_lever, PROMPT_INSERT_LEVER}`; test `lever_pickup_drop_and_crank`.
## Gaps
Where levers lie in each level (pickup objects, `G+0x456c = 10` set by the pickup actor) is level data.
