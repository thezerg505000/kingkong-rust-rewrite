# J01 Forward movement (main doc for J01-J04, J07; see also J05, J06)
## Behaviour (what the game does)
Jack has no jump and no separate strafe/back speeds. Every frame `GG_Exec_Joy` turns the left stick into ONE
world-space horizontal direction (stick rotated by the camera object's matrix, Z dropped, normalised) and
`H_exec_select_action` moves Jack along that direction at a speed chosen from the stick magnitude and a few
state flags. Forward, backward, strafe and diagonals are therefore the same mechanism (camera-relative analog
movement). Jack is "running" by default (`i_flag_run` is forced to 1 every frame by `H_exec_read_joy`); holding
the aim/ready buttons with a weapon equipped clears it and Jack walks (x2.5) and, with the aim flag, creeps at 0.5.
Crouch is x1.5. Speed eases toward the target with a 4/s blend and is zeroed (instant stop) when the stick is
released. The vertical velocity component is left to the engine's physics/collision.

## Code
- `GG_Exec_Joy@0x695030` (called from GST_Global_go): `fn@0x43cb00` (stick, per-axis deadzone) -> v = -stick;
  |v| = L; if L < 0.25 everything is zeroed; else v rotated by camera matrix (`fn@0x41ccc0`), Z := 0, normalised ->
  Univers+0x2c..0x34 (move dir); Univers+0x68 = clamp((L-0.25)/0.675, 0, 1) (set to 1.0 above 0.99). A latch (+0x74)
  keeps the previous direction while the camera forward flips by more than 45 deg (dot < 0.7071) until it settles (>0.9).
- `H_exec_read_joy@0x579f30`: copies Univers+0x2c/+0x68 into Jack +0xc50 (direction) / +0xc4c (magnitude)
  (`if +0xc48`); sets run flag +0xba8 = 1, clears it when button 4 or 6 is held with a weapon (and +0xed2 == 0);
  ready ramp timers +0xc08/+0xbac; crouch (+0xb60, see J06); aim (+0xb94).
- `H_exec_select_action@0x587bd0`: player branch (`*this != 0`) with +0xc4c != 0 (L > 0.25): target speed (below);
  `+0x1ab0 = (1-k)*+0x1ab0 + target*k`, k = clamp(4*dt, 0, 1); velocity = +0x1ab0 * dir(+0xc50..) with X,Y from
  the direction and Z copied from the current velocity (`fn@0x433890` get / `fn@0x433790` set). Stick inactive
  branch: `+0x1ab0 = 0`, velocity (0,0,vz) (select_action lines ~1412-1425).
- `fn@0x433790` Dyn_SetSpeed -> `fn@0x4337d0` writes `obj->dyn+8..0x10 = v * (1/dyn+0x20)`; `fn@0x433910` is the
  inverse getter. The per-frame integration + collision that consumes this speed is engine code that was not located
  (see Gaps). `H_TRACK_Post@0x5c8370` overrides the speed (adds a push vector at +0xed3.., zeroes it when wound state == 3).
- dt is the global `DAT_012f797c` (seconds; all timers in these functions subtract it).

## Data
Jack struct = model `m733_i_etat_courant` (ff0003eb); the offset->name map in `models.json` is unreliable at these
offsets (names are nearest-neighbour), so offsets are given by number. No ova/ofc statement was needed for these constants:
all speeds are literals in the code. `i_mode_script` (+0xb1c) values 3/9/0xb/10/0xc are the water-capable modes (names L).

## Rust
`kk_mechanics::jack`: `stick_magnitude`, `move_direction` (GG_Exec_Joy), `MoveInput`, `MoveState::{target_speed, step}`,
`MoveOutput`, constants `SPEED_*`, `CAP_*`, `READY_RAMP_TIME`, `WADE_DEPTH_*`. Tests: `target_speed_table`, `caps_and_wading`,
`ready_ramp_runs_4_5_to_2_5_in_a_tenth_of_a_second`, `step_smooths_with_four_per_second_and_keeps_vz`, `move_direction_thresholds`.
The old `kk_fps::player` should switch to `MoveState` (the old notes "walk 2.5 / run 4.5 / crouch 1.5" were right, but the
direction/zero-below-0.25/ready-ramp behaviour is new).

## Gaps
- Unit of speed: assumed metres/s (Jade world unit = 1 m, [L]); the DYN integrator that scales by dt was not found.
- Engine collision call: none in `H_`; movement is "set DYN speed, engine slides". Candidates not verified: the engine
  step that reads obj->dyn+8 and +0x20.
- Axis/sign convention of the pad layer (`fn@0xa6be80` components 0/1) and of the camera local axes is [L]; `move_direction`
  takes the camera axes as arguments.
- Body turn toward the move direction (tail of select_action, `fn@0x692870`, rate var +0x1018) not ported; first-person view is
  driven by CM_Cam, not by the body.
- Anim ids chosen per weapon (local_50: 0x32..0x37 moving, 0x3a.. aiming, 0x28..0x2d idle) recorded in J07/J08 only partially.
- Frame-rate compensation in `fn@0x414520/00413750` (`DAT_00b9ae28`) ignored.
