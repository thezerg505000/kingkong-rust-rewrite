# I07 Ammunition pickup
## Behaviour (what the game does)
An ammo box (`Munition`) holds up to 10 pickups; each use gives the player one clip's worth of reserve
for that box's weapon and consumes one pickup. Using it with a full reserve does nothing (message).

## Code
- `Munition_init` @0x6c45a0: `if (10 < this[1]) this[1] = 10` (pickup count cap) [C]; this[0] = weapon type, this[5] random start slot; per-box state
  `G+0xf2c+4*id` (float count shown).
- `Munition_wait` @0x6c4000: 10 visual slots; on use (`flag 0x8000`): `gap = reserve_max - reserve` (`G+0x3f80 - G+0x39d8` at w*0x48); `gap==0` -> message 0xd0005ae9 (full);
  else sets `G+0x456c = weapon+0x15`, `G+0x4570 = actor`, and `this[1] -= 1` after the pickup event [C].
- `H_TRACK_Reflex` @0x58de70 (bytes 0x58f1b0..0x58f2a0): `w = G+0x456c - 0x15`; `t = reserve + clip[w]`; `if reserve_max < t: reserve = reserve_max else reserve = reserve + t` [C] (literal asm
  `mov eax,[reserve]; add eax,[ebp-0x88]`), i.e. 2*reserve + clip when under the cap.

## Numbers
| value | where | conf |
|---|---|---|
| box capacity 10 pickups (not 10 rounds) | Munition_init | [C] |
| one pickup = reserve + clip(w) (cap reserve_max), literal formula 2r+c | H_TRACK_Reflex asm | [C] |
| full reserve refuses pickup | Munition_wait | [C] |

## Rust
`weapons::{AmmoBox, Ammo::apply_box_pickup}`; tests `ammo_box_count_capped_at_ten`, `ammo_box_pickup_is_refused_when_full_and_follows_the_compiled_formula`.
The old `pickup(count)` ("reserve += min(count,10)") misread the cap as rounds and was removed.

## Gaps
Grenade box (`weapon 5`) takes a different path (`G+0x456c = 5`); companion hand-over of ammo not researched; whether 2r+c is intended is unknown (shipped behaviour kept).
