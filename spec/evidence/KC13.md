# KC13 Button-mash finish
## Behaviour (what the game does)
Two mash systems exist. (1) The V-Rex jaw-break tug-of-war (KC11, `KT_ETAT_Finish`). (2) The generic **GrabKong
mashing challenge**: Kong state `k_ETAT_grab_mashing` (action id 0x160) against any object/creature that offers a
"mash kit" - a creature that grabbed Kong (a rex bite, raptor, ...) or a `KInteractive_Mashing_Object` (KIMO). A challenge animation
plays; every mash press kicks Kong's input energy up, the energy decays, the opponent's counter-force builds when
Kong's energy is low; the net force moves a cursor along the animation. Reaching the end wins; falling to the lower
threshold loses. Presses only count during the first 4.5 / 10 / 8 s of the challenge.
## Code
* `k_ETAT_grab_mashing@0x8cca60` (Kong side). Dt is clamped to [0.016, 0.048]. Kit data (45 dwords from the
  opponent kit +0x10) is copied to `Kong+0x5d0..`: decay rate `+0x77c`, counter-force gain `+0x780`, energy threshold
  `+0x784`, counter-force reduction per press `+0x788`, press energy `+0x78c` (= 2 x kit+0xd4), cursor lose-threshold
  `+0x774`, cursor end `+0x778`, mode `+0x5c8` (1,2,3).
  Per frame: `scale = 1 + (stall - 0.5)/2` when the stall timer `+0x4c8 > 0.5`; if energy `+0x4bc < +0x784`:
  counter `+0x4c0 = min(+0x4c0 + gain*dt*scale, 10)`; energy `+0x4bc = max(+0x4bc - decay*dt, 0)` where decay =
  `+0x77c` (x0.5 in fury, x3.0 and gain x2 if the kit's "hard" callback is set); on a mash press (`Kong+0x7c` or
  `Kong+0xa4`, and state time `Kong+0x68` < limit, and not blocked by `fn@0x888960`/`Kong+0x1ac8`):
  energy `+0x4bc = +0x78c / scale`, counter `-= +0x788` (floor 0). net = energy (- counter in modes 2/3); if net < 0 the
  stall timer grows; the velocity `+0x4c4` slews toward net by at most `dt * fn@0x425650(anim)`; cursor `+0x76c += velocity`
  per frame. State messages to the opponent: 0x20 positioning, 0x21 challenge running (progress), 0x22 won, 0x23 lost, 0x24
  cancelled, 0x25 interrupted. The win/lose animations are `Kong+0x5c0` / `+0x5c4`.
* `KIMO_ETAT_Mashing@0x4c8090` (opponent = mashing object): on 0x21 sets its animation cursor to
  `max(progress, previous)` (`fn@0x7dd290(msg)`, `fn@0x425cb0`) with the anim frozen (`fn@0x426f80(self,1)`); on 0x22 jumps to
  result state `KIMO+0x3f` (win), 0x23 to `KIMO+0x40` (lose), 0x25 to `KIMO_ETAT_Mashing_Interrupted@0x4ca0d0`, 0x24 cancel
  (returns to the idle `KIMO_ETAT_Wait@0x4c7cf0`); any other kind logs `"KIMO_ETAT_Mashing : Erreur dans
  LNK_GrabKong_Mashing_Result_Get()"`. `KIMO_exec_propose_grab@0x4c8d70` offers it to Kong when within 11.0 (dist^2 <= 121.0); the proposal weight is
  dist^2 + 8000 (+200 more when the axis test `bad axe` passes) `[L]` and carries message mask 0x40, id 0x20. `KIMO_ETAT_Projete@0x4c9780`: the object after a throw.
* Press window: `max_time = 4.5` for challenge type `Kong+0x4cc` 4 or 5, `10.0` for 6, else `8.0` [C].
## Numbers
dt clamp 0.016/0.048; counter-force cap 10.0; stall assist `(stall-0.5)/2 + 1` for stall > 0.5 s; press windows 4.5/10/8 s; KIMO
propose radius 11.0 (121.0 squared); fury x0.5 decay; initial cursor velocity 0.01 (0x3c23d70a) [C]. The kit numbers (decay, gain,
threshold, per-press energy, lengths) are per-opponent data: **press counts cannot be derived from the exe** `[gap]`.
## Data
Kit data: `KIMO_InitFromKit@0x4c9af0` copies it from the level's kit object; the rex's own grab kit is the object passed as
`KT_exec_grab_object_param@0x4b1660` (`fn@0x7dd8e0(.., 0xc, .., S:KT_exec_grab_object_param)`).
## Rust
`kong::vrex::FinishMash` (the rex jaw-break variant) and `kong::fury::FURY_MASH_DECAY_MUL`. The generic GrabKong challenge is not
ported yet (needs kit data); the equations above are the spec.
## Gaps
Kit numbers, button identity of "mash" (`Kong+0x7c` = slot 4, `Kong+0xa4` = any-button), and the HUD prompt.
