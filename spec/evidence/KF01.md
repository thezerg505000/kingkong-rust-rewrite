# KF01 Fury activation (main fury document; KF02-KF07 point here)
Kong's fury ("furie", also "rage" in the model variable names) recovered from Kong's own AI
(`k_*`, model m724-like, not the `KR_*` family: **`KR_` is the Kong-level Raptor**). Tags `[C]` read
from decompiled/disassembled code, `[L]` inferred, `[G]` guess. Kong's struct offsets are `Kong+0xNNN`.
Decompiled for this pass with the project's Ghidra (the shared KB export stops at 0x6f1860, so the
`k_*` functions at 0x88xxxx-0x8fxxxx were exported on demand).

## Behaviour (what the game does)
In the combat chain, a **third** attack input followed by the fury button starts the chest-pound
(`anim 0xab`, combat phase 4). While the button is held, the pound's time budget keeps growing, and a
growing shout stimulus (radius +10/s up to 30) goes out. When the animation passes frame 130 with
the button still held and no other attack button pressed, Kong roars (`anim 0xad`) and **fury starts**:
an 18 s timer. During fury Kong's blows do double damage (and always count as heavy hits that can
knock the rex down), all his animations play 1.25x faster, he cannot be killed (life 0 becomes 10),
mash/pull struggles tilt in his favour, and the screen/audio are re-graded. Every landed blow adds
1.5 s (capped at 15 s); every hit he takes cuts 2.5 s or 5 s. When the timer runs out fury ends.
Creatures that hear the shout roar back (rex) or react (raptor, bats).

### Activation (KF01) [C unless noted]
1. Phase machine (`Kong+0x1adc`): `fn@0x884b00` (phase 1), `fn@0x884d40` (2), `fn@0x884de0` (5),
   `fn@0x884e70` (3), `fn@0x884f00` (**4**), `fn@0x884f60` (6), `fn@0x885010` (9 = end). Inputs are
   latched in `Kong+0x1acc/0x1ad4/0x1ad0/0x1ad8` = button slots 1/2/3/4 (`fn@0x884600(n)`; slot n reads
   `Kong+0x8c/0x78/0x90/0x7c` held flags, `fn@0x884700(n)` tests the pad edge mask 0x20/0x40/0x80/0x80).
   The ledger text says **Triangle**; the mapping of slot 2 to the PS2 face button is `[L]`.
2. In phase 3 (`k_ETAT_main` case 3, disasm 0x89b6cf): `fn@0x884600(2) != 0` and `*(Kong+4) == 0`
   -> `fn@0x884f00()` (phase 4, anim 0xab). If `*(Kong+4) != 0` the same input does something else (ends phase).
3. Phase 4 (`k_ETAT_main` case 4): each call with `Kong+0x78 != 0` (button 2 held/active) adds
   **0.2** to the budget `Kong+0x7c0` (`_DAT_00a88e1c`; start **0.5**); `Kong+0x7bc += dt` is the elapsed time. The
   phase ends (idle, `fn@0x887390`) when `budget < elapsed` or the animation ended. So the pound survives
   only while the player keeps pressing (each pressed call buys 0.2 s) - "repeatedly press".
4. Resolution: `(Kong+0x78 != 0 && animframe(0xab) > 0x82)` **or** (`fn@0x884780` anim-flag 0x100 and a latched
   slot-3 press). Then, in order: slot 3 latched -> grab branch; else slot 4 -> `fn@0x8eaaa0` (cancel to idle);
   else slot 1 -> `fn@0x8851a0`; **else `fn@0x883430(0xad)` = fury starts** (disasm 0x89babf-0x89bb6b).
5. **Fury meter** (`Kong+0x7d4`, "charge"): `fn@0x883700` (called once per attack action from the hit-landed hook
   `fn@0x883050` when the victim has life > 0): if fury is off, meter += 0.1 (`_DAT_00a88c48`), +0.1 again if
   `Kong+0x1fc4` (set when Kong is wounded, `k_reflex`), +0.1 if the victim is wounded (Life gauge), +0.1 if the
   hit-message type has bit 1 or 4 (`& 5`); outside phases 4/7 a meter above 0.8 is reset to 0.7. **No code
   compares the meter against a threshold to allow fury** (scan of all `Kong+0x7d4` reads): it is HUD/FX state `[L]`.
   The only gate is the input sequence above.
6. Cannot start another fury while one runs: during fury `fn@0x883700` takes the extend branch instead.

### Duration, extension, termination (KF07) [C]
* Start: `Kong+0x7c4 = 15.0` then `+= 3.0` -> **18.0 s**; `Kong+0x7d4 = 1.0`, `Kong+0x7d8 = 1`.
* While on, each landed blow (once per attack action): `+= 1.5` (`_DAT_00a88e70`), then `> 15.0` -> 15.0 (so the first
  blow after the start brings 18.0 down to 15.0, later blows refill up to 15.0).
* `k_exec_fury`: timer -= min(timer, dt) every frame (real time), **except** while Kong's action id (`Kong+0x5c`) is
  0x352, 0x353, 0x160 (grab/finish mashing) or 0x15e (unless `fn@0x606b30(kong,0)` is non-zero); the sentinel
  `0x56b5e621` (1e14) = "infinite fury" is never counted down. At 0 the meter (`+0x7d4`) and flag (`+0x7d8`) are cleared.
* Hit penalty (`k_ETAT_paf`): if timer > 5.0: `-= 2.5` when the hit flags `(Kong+0xc74 & 3) == 0`, else `-= 5.0`; if Kong
  is wounded (his Life gauge `Kong+0x1aa0`), the result is clamped to [5.0, 15.0].
* Cleared outright (`= 0`, meter and flag too) in `k_ETAT_finished` (Kong dies/finished) and in `k_reflex` when `Kong+0x1e38`
  (death code) or `Kong+0x1eb8` (cinematic) is set.
* `fn@0x8836a0(x)` (called from `k_ETAT_jump`): timer = max(timer, x) - a way for scripted jumps to guarantee fury time `[L]`.

### Effects while fury is on
* Damage (KF04): Kong's melee blow base damage is 10 (`mov [ebp-0xe4],0xa`), with fury 10 + 10.0 (`fadd _DAT_00a88e24`) = **20**,
  and the hit class sent is 2 (heavy) instead of 1 (`fn@0x88e0c0@0x88e0c0`, three sites 0x88ea37, 0x88eb9e, 0x88f07f).
  Class 2 + fury also makes `fn@0x559f20` accept the hit as a knock-down on the rex (see KC10).
* Aggression (KF03): at the end of `k_ETAT_main`, animation speed = `ftol(animSpeed(fn@0x4244e0) * 1.25)`
  (`_DAT_00a89194` = 1.25) while fury is on (disasm 0x8a4064-0x8a40b4); otherwise unscaled.
* Resilience (KF05): see KF05.md. FX (KF06): see KF06.md. Chest pound/shout (KF02): see KF02.md.

## Data
Kong's life gauge (`Kong+0x1aa0`, max/start/wound ratio) and the fx colour values
(`f_fury_afx_*`, per-level instance data, see KF06) are not in the exe. The Kong model m724 in
`ova/models.json` lists `f_Fury_time_end 0x7c0`, `i_fury_on 0x820`, `f_fury_charge 0x8d0`, `f_fury_puissance 0x7f8`,
`i_fury_step 0x7b4`, `f_fury_charge_time 0x7e8`, `v_fury_axis 0x7c4`, `f_time_fury 0x7cc` etc.; the real use of
`0x7c4` (timer) and `0x7d4`/`0x7d8` shows that several of those names are mis-offset by the scan (v_fury_axis is
a vector, but code reads a float timer at 0x7c4). I name by use.

## Gaps
* Which PS2 button is "slot 2" (assumed Triangle from the ledger text).
* `Kong+4` (the `== 0` test in phase 3, also passed to the message poll `fn@0x7dd5b0(0xc, .., Kong+4==0, ..)`) is a mode/remote-control flag whose meaning is unknown `[L]`; with it set, the fury input does not start the pound.
* Frame units of `fn@0x425950` (60 Hz assumed `[G]`), so the real-time length of the 130-frame pound is unknown.
* Meter semantics (HUD?) and `Kong+0x7d8`'s consumer are not found.
* Per-hit damage of other Kong attacks (grab moves, ground pound) is in the grab/jump functions and was not
  audited for fury scaling; only `fn@0x88e0c0` was.
* PS2 build may differ in timer units and in the fury button.

* AUDIT 2026-10-07: annotated 0x38d1b717 in the fury-start stimulus call as the float 1e-4 s message lifetime, not a message id (evidence fn@0x6e4680@0x6e4680 passes it as param_3 to fn@0x43b580 -> record word [1]; fn@0x43b360@0x43b360 decrements it by dt; the stimulus kind is queue 0x14).
