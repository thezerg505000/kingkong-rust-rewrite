# N11 Companion protection / failure conditions
## Behaviour
No code was found that fails the mission when a companion dies: companion death (`H_ETAT_IA_mort@0x5a3e80` with `this[0]==0`) plays the death and records the status 3; `fn@0x52f240` (game over + death stats) is called from the death state `H_ETAT_IA_mort` (timers 1.0 / 4.0 / 8.0 s) and from `k_reflex` (Kong); which instance (Jack or the AI companion carrying flag `this[0x2a9]`) runs each branch is not separable in the decompilation. Protection objectives therefore live in level scripts that test the status (`TrigExec_EtatHumain@0x78b3c0` writes it; script tests read `G+0x1bb4+4*slot`), not in AI code [L].
What does exist: Jack's own death is *delayed by a healer*: in `H_ETAT_IA_mort` Jack's healer reference (`this+0x1a18`, set by Ann's heal order) lets the death timer pass 4.0 s without game over while the healer walks to him; with no healer or a healer timer > 0.5 the game is over at 4.0 s, and at 8.0 s when the healer never started (`healer.flag 0x2e48 == 0`) [C]. If Ann reaches Jack he is revived (status 0, `fn@0x53a0f0` line 0xd0005158).
