# I10 Lever carrying
## Behaviour
The lever is weapon-slot item **10**. Picking it up (a pickup actor sets `G+0x456c = 10`, `G+0x4570 = Jack`; `H_TRACK_Reflex@0x58de70` ~lines 548-575, or the script `FORCE_ETAT` sub-code 5 value 10 which sets `G+0x4588 = 1` directly) is refused if Jack already holds item 10 in hand or stash; otherwise anim 0x66, `fn@0x68c870` first drops whatever throwable he holds, `G+0x4588 = 1`, the previous hand item goes to the stash cell (`G+0x3390+4p`) if that is empty, and item 10 goes in hand (`G+0x3344+4p`). The lever is therefore carried "in addition to" regular equipment: the weapon is only stashed and comes back when the lever is dropped or inserted. Swapping hand/stash with the weapon button (`H_exec_read_joy`: buttons 4/6 when item 10 is in hand and not swimming, or the pad swap when the stash holds 10) toggles between the lever and the gun (aim animation set 0x67/0x5d with item 10).
Dropping: `fn@0x68c870@0x68c870` (called from almost every state change: use, carry, heal, hit-reaction, death, `H_TRACK_Reflex` on water) spawns the lever object (`DAT_00b99798`) at the hand bone, clears `G+0x4588`, restores the stash into the hand and, if a lever was holstered in `G+0x33dc` for cranking, moves it back to the stash. While cranking (`H_ETAT_Ia_porte`) the lever in hand is holstered (`G+0x33dc = 10`, hand 0) and restored on exit.
Inserting it into a pillar socket is E10.md. `TrigTest_Levier` lets scripts test the flag.
