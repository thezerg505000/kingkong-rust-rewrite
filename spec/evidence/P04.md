# P04 Automatic checkpoints (and P05 restart)
## Behaviour
Walking into an ES_CheckPoint trigger stores its id in `G+0xc` and takes a snapshot of every Univers variable flagged 0x10 plus the persistent-object id table. On death the map is reloaded with entry id `G+0xc` and the snapshot restored, so progress, weapons and ammo go back to the checkpoint while time, deaths and variant count survive.
## Code
- ES_CheckPoint@0x6f49a0: if `G+0xc != this[1]`: `G+0x4dc8=0`, `G+0x4dcc=0`; `G+0xc=this[1]`; clears actor flag 0x4000; sets destroyed bit via fn@0x432d50(G+0xc08,id) (ids >= 15000 clear bit id-15000 via fn@0x432de0); calls fn@0x43d690 (snapshot save), optionally runs an action fn@0x412440 [C].
- fn@0x43d690@0x43d690 (Checkpoint_Save): copies all Univers vars with flag 0x10 to DAT_012e1508 and the 0x2f40-byte table DAT_00b95b70 to DAT_012e6508. fn@0x43d7f0 (Checkpoint_Restore) is the inverse [C].
- fn@0x43d510 Profile_SaveVars: vars flagged 0x40 into profile [C].
- Stats_OnPlayerDeath@0x52f240 caches stat[+0x00],[+0x08],[+0x14] into G+0x2da0/4/8; GST_Global_init@0x693c50 writes them back after reload [C]. Restart gated by `*DAT_00b99774 != 0`.
