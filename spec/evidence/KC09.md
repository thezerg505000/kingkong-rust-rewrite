# KC09 Combat dodge
Main document: `spec/evidence/KC01.md`. K05 (movement agent) covers the same button from the movement side.

## Behaviour (what the game does)
The jump/roll button (latch slot 1, pad index 2, `Kong+0x8c`) runs `fn@0x8851a0` (`k_ObstacleResponse`). It first raycasts 5.0 ahead
(`Raycast_Object`); a climbable obstacle / ledge leads to the climb-over logic (K06-K08). With no obstacle the result is a dodge:
* **Roll** (phase 7, anim 0xe): default. Direction = the stick direction (`Kong+0x13f8`), snapped by the auto-aim (`fn@0x882990`, cone cos 30 deg = 0.866,
  distance limit 20.0, search 100.0) to an enemy. The roll lasts as long as anim 0xe; `Kong+0x70 = 1` while it plays. The roll is **not**
  invulnerable (anim 0xe is not in `Kong_IsInvulnerable`).
* **Side-step** (phase 8, anims 6 and 7 = left/right `[L]`): chosen when an enemy target `Kong+0xcf4` exists in front: squared distance <= 196 (14 units)
  and dot(stick, direction to target) >= -0.342 (cos 110 deg), and the target class is one of the dodge-able attackers; anim 6 or 7 by the sign of the side dot.
  Kong is invulnerable while anims 6/7 play (`fn@0x604370`; `k_exec_detect_paf` also skips hits from creature class b99f88 during 6/7). After the side-step
  ends `Kong+0x1164 = 5.0`, `Kong+0x1168 = 1.0` and `Kong+0x70 = 0`.
* **Chaining**: during the side-step a second press is accepted after anim frame 0x37 (55) provided fewer than two riders are on Kong.
* **Riders block it**: `k_exec_button_latched(1)` returns 0 while `k_GetRiderCount (Kong+0x1110) >= 2` (up to 5 rider slots `Kong+0x10cc`, polled by `fn@0x888a00`
  via message type 3), and the idle start is skipped entirely in that case.
* **Counter**: attack during or right after the dodge (phase 7/8, attack latched) = counter lunge (KC03).

## Code
