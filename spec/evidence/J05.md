# J05 Free camera (look)
## Behaviour (what the game does)
The right stick turns the camera (Jack's view). Yaw and pitch rates are the stick value times twice the options "sensitivity" times 10 times a
factor chosen by mode (run 3.0/1.75, normal 2.0/1.75, lock-on 1.5/1.31, aim 0.6/0.35, special 9/5.25), per second. Full horizontal deflection
(|x| > 0.95) while not aiming builds a cubic yaw acceleration: the yaw factor gains t^3 where t grows with dt up to 1.2 s (1.0 aim / 1.0 lock-on / 3.6 special).
Pitch has no ramp. Pitch is limited by clamping the forward vector's Z to +-0.95 (71.8 deg). An options flag inverts the vertical axis.
Values smaller than 0.01 after scaling are dropped (a tiny software deadzone; there is no deadzone function on this stick).

## Code
`CM_Cam@0x45b1b0` (25958 bytes; Ghidra's decompile times out, so everything below is read from the disassembly with addresses):
- 0x45d544: right stick = `fn@0x43cda0` -> `fn@0xa6be80(out, 1)` raw pad layer. Zeroed x if camera +0xf0 or Jack +0xc1c != 0 (0x45d59a, 0x45d5be);
  y negated if camera +0x18 (0x45d647); camera +0x14 request zeroes both.
- 0x45ebb2-0x45ecf9: factor selection in this order: G+0x337c != 0 -> (9, 5.25, ramp 3.6); Jack +0xb94 (aim) -> (0.6, 0.35, 1.0) and x1.5 both when G+0x3348 == 0 (no weapon);
  Jack +0xba8 (run) && Jack +0x3b48 == 0 -> (3.0, 1.75, 1.2); lock-on actor (Jack +0x2d00 validated) -> (1.5, 1.31, 1.0); else (2.0, 1.75, 1.2).
- 0x45ed1d: stick clamped to [-1, 1]. 0x45edda: if |x| > 0.95: ramp = min(ramp + dt, cap) unless aiming (then ramp := 0); yaw factor += ramp^3; else ramp := 0 (camera +0xc).
- 0x45ef04: free look runs when there is no lock-on target (+0x58 == 0) or Jack +0x3390 != 0.
- 0x45eff8: if G+0x4db8 (invert) y := -y; x,y *= 2 * G+0x4dbc (sensitivity). 0x45f04e: |v| < 0.01 -> 0.
- 0x45f0c8-0x45f193: yaw `fn@0x414520(obj, -x*10*dt*yawFactor)` (rotation about Z; to camera object +0 when Jack +0x3390 != 0, else Jack body);
  pitch `fn@0x413750(obj, -y*10*dt*pitchFactor)`; when Jack +0x3390 != 0 also camera +0xa8 += 2*(-y*10*dt*pitchFactor).
- 0x45f281-0x45f351: forward vector Z > 0.95: xy normalised * 0.31225, Z = 0.95; Z < -0.95: Z = -0.95 likewise.
- `H_exec_read_joy` and `GG_Exec_Joy` do not touch the right stick. Options menu `IntMIG_Page_OptStart_Control@0x61dfc0` edits G+0x4db8 (invert) and G+0x4dbc (sensitivity).

## Data
G+0x4db8 / +0x4dbc are options in the Univers-like struct `DAT_00b98cf0` (the options menu uses `DAT_00b99608`, `fn@0x4daa80` uses `DAT_00b98f54`); the names
CAM_InvertMouse / CAM_MouseSensitivity in earlier notes were guesses from the menu code, still [L].

## Gaps
- Sensitivity default (needs the options defaults / save init); range of the slider (0.08-0.97 appear as slider bounds in the menu draw code, not confirmed as the value range).
- Right-stick device scaling inside the pad layer (`fn@0xa6be80` / `fn@0xa6bfe0` multiplies index 1 by a constant at 0xa88f64) not read.
- Frame-rate compensation `DAT_00b9ae28` in the rotate functions (scale = _DAT_00b9a330 / (fps/60)) ignored.
- Earlier note "turn rate rad/s = stick * 10 * factor" was missing the 2*sensitivity term; the ramp is cubic in time (confirmed).
