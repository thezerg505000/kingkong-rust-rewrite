# C10 Camera injury effect
Status: PARTIAL. What is known [C]: Jack's hit receiver sets camera reactions (H02.md: `fn@0x423e30(cam, 0x80000000 | 0xa | 0xb | 2)` + damping fields) and rumble; the wounded heartbeat pulses the camera parameter `fn@0x6932f0(..., 0.52)` (H05.md). `Msg_SendJackScreenFx@0x6e5060(out, code, target)` enqueues a record in message queue 0x16 via `fn@0x43b580(target, 0x16, 0.0001, payload, 1, out)`: **0x38d1b717 is the float 1.0e-4 (a delay), not a message id** (the earlier hypothesis was wrong); the code goes to payload offset 0x54 (record word 0x17). Codes sent: 2 on hit (`H_ETAT_IA_paf@0x594400`), 4 each frame of death (`H_ETAT_IA_mort`) and of status 3 (`H_TRACK_Reflex`), 5 each frame of a medium/heavy wound; also sent by `Na_Reflex`, `KAnn_ETAT_paf`, `KT_ETAT_I_Finish`, `KR_ETAT_Finish_on_KONG`, `KBC_ETAT_KK_Finish`, `GEX_Go/End`, `SIG_Loop`, `SPM_Loop`, `IOB_Etat_Go`, `PluieDeLances_etat_attaque` (so the code is a general "fx request", not Jack-specific). The only `fn@0x43bd70(0x16,...)` consumers in the KB are `KPJ_Plug_testSIG` and `Javelin_Plug_testSIG` (filter code 0xff), so no C consumer applying red/blur was found; the post-process (AFE_*) is probably driven from the engine/script side that the KB export does not decompile. No fade/blur numbers. Gaps: find the reader of queue 0x16 records (scan for raw `0xb45430` access or the script interpreter).
