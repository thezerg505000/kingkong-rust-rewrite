# E12 Movable obstacles
## Behaviour
Kong-level objects Kong can grab, carry and throw are `KIGO_*` (Kong Interactive Grab Object: `KIGO_init@0x671970`, `KIGO_ETAT_attente_grab@0x671f30`, `_grabbed@0x672490`, `_projectile@0x6744d0`, `_impact@0x675760`, `_tombe@0x676570`, `_explose@0x6769c0`, `KIGO_callback_set_pos@0x6727e0`) and `KIMO_*` (mashing objects: button-mash to move/lift, `KIMO_ETAT_Mashing@0x4c8090`, `_Projete@0x4c9780`). `KIGO_init`: box half-extents +-8 (`0x41000000`) as collision, default carry offsets (0,0,1.5), two values copied from a global model (`+0x1c98`, `+0x1ca0`), constant 81.0 (`0x42a20000`, `this+0x120`, meaning [L] mass/strength). `KIGO_exec_check_paf` sums incoming paf force vectors (z zeroed, normalised when non-zero) into `this+0x1f0` (push direction). A thrown object stays in `impact` until it settles (`|dz| < 0.05` per frame, `0x3d4ccccd`), then returns to wait; explode state scales with 0.2 factors. The movable-boulder-in-a-passage behaviour is therefore a KIGO placed with a level script; no separate "obstacle" class.
## Code
`KIGO_*` (23 fns), `KIMO_*` (12 fns), `KIODE_*@0x6a4f60..` (Kong-level ODE props: `KIODE_init` uses box +-6 half extents and a 200.0 parameter (`fn@0x436550(self,0,0x43480000)`); `KIODE_exec_check_paf` turns any incoming paf into a force of `1000/dt` times the paf direction (`fn@0x435ff0`) and wakes physics).

Mostly structural constants (above) [C]; no thresholds for "heavy enough".
