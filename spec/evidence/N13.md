# N13 Formation progression (pointer: N01.md, N12.md)
## Behaviour
Companions "move ahead" when the level script releases them: `TrigCINE_ResetWaitDefault` (0x186a6) clears their waiting state and `H_exec_ch_msg` sub-command 0x186a4 empties the queue and returns the actor to its saved follow state (`this+0xb08` etc.). `TrigExec_EtatHumain@0x78b3c0` writes a status value straight into `G+0x1bb4+4*slot` (script sets wound state, 1 float). Through `FORCE_ETAT` (0x186a7) sub-codes the script writes per-actor parameters: sub 0..4,6..0x18 integer variables (e.g. `+0xaa4`, `+0xaa8`, `+0xab0`, `+0xab4`), 0x19 = `this+0x41d0` (float, the "stunned/help" limit), 0x1a = `this+0x41e0/0x41e4`, 0xc sets the actor's wound status 3 (dead), 5 gives an item (see I10) [C].
Progression of the pack through the level is otherwise the follow state with the override distance `this+0x1930` or leader `this+0x193c` that the script changes [C].
## Rust
`companions::cine`, `force_etat_give_item`, `follow_distance`.
## Gaps
No explicit "formation ahead of Jack" logic exists in code: it is waypoint/leader selection from level data.
