# W07 Dynamic encounter music
## Behaviour
A music scheduler picks a phase (-1..6) from counts of threat "beacon" messages; the phase is held in G+0x4d80 with kit G+0x4d84 and level scripts test it (TrigTest_MusPhaseEqual/Higher). A phase must persist 0x10 ticks before switching; leaving phase 3/4 (combat) is delayed by a timer.
## Code
SM_Scheduler@0x51ca40 (state machine this+4: 0,10,0x14,0x1e,0x28,0x32,0x3c,0x46,0x5a,100,0x6e), SM_Scan_Phase_Kit@0x51e2b0, SM_Scan_Jingle@0x51d7b0, SM_ReinitKit, SM_ScriptMode, SM_Init_Map; Kong version SKMM_ScanMessage@0x6b7c30 [C].
Phase rule (SM_Scan_Phase_Kit): count5 !=0 -> 5; script flag -> state 100; else 3 (or 4 if this[0x28c] or condition @+0x11ac) if count[0x288] and persist>=0x10; else 2 if [0x29c]; else 1 if [0x284]; else 0 if [0x290]; else unchanged. Counter smoothing fn@0x561420 [C].
SKMM: message type 0x16 codes 0/100,1/0x65,3/0x67,4/0x68,5/0x69,6/0x6a -> phase 1,3,0,special,5,2 [C]. Jingle code 200 sets this[0x2e8]/[0x2ec], state 1000.
## Numbers
persist 0x10 ticks [C]; per-phase timings are model data (+0x1138..+0x1290) not decoded.
## Data
model tables read via fn@0x561480/4c0/550/5e0/670/710.
## Rust
`progression::MUSIC_PERSIST_TICKS` only.
## Gaps
Timing values, kit contents, which beacon classes map to which creatures.
