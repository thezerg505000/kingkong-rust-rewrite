# G11 Shotgun spread
## Behaviour (what the game does)
One trigger pull on the shotgun (weapon 3) casts 25 rays in a 5x5 angular grid spanning +-10 degrees,
each angle perturbed by a random +-0.05 radian (about +-2.9 degrees), except the centre ray which is exact.
Each ray can hit a different creature; damage per ray comes from the usual distance bands.

## Code
`H_callback_tir` @0x5bbd10, `case 3` (around the lines with `for (local_1f4 = 0; local_1f4 < 0x19; ...)`):
- locals `local_200` and `local_1e8` start at `-0.17453292` (= -10 deg in RADIANS) [C]
- per pellet: if pellet index != 0xc: `angle += fn@0x41c450(0.05, -0.05)` for both angles [C]
  (`fn@0x41c450` = `Rand_Range(a,b)`: returns a if a==b else `fn@0x41c480`)
- the angles rotate the aim vector (`fn@0x41d730`, axis built from `fn@0x41cb40` cross product), so the unit
  of both the grid and the jitter is the ANGLE in radians, not a direction-vector component [C]
- after each pellet: `local_200 += 0.08726646` (5 deg); `if (0.17453292 < local_200) { local_200 = -0.17453292; local_1e8 += 0.08726646; }` [C]
- each ray is cast by `fn@0x42d400` (`Raycast_Object`, mode 0xb) with length `local_4ac = 25.0` (equals range G+0x465c+4*3 = 25) and damage from `fn@0x53a370(3, fn@0x4150e0(...))` [C]
- extra per-pellet values `local_1fc` (-0.5..0.5 step 0.25) and `local_1e4` only offset the tracer origin passed to `fn@0x40b5e0` (visual) [L]

## Data
Shotgun row of uni_init: R1 5, R2 10, range 25, clip 5, damage 20/10/5.

## Rust
`weapons::shotgun_pattern` (faithful f32 accumulation, centre pellet unjittered), constants
`SHOTGUN_HALF_SPREAD, SHOTGUN_STEP, SHOTGUN_JITTER`; tests `shotgun_grid_is_25_pellets_in_radians`,
`shotgun_jitter_is_plus_minus_0_05_radians_and_skips_centre`. The previous version treated the jitter as a
direction-vector offset [L] and jittered the centre pellet: both corrected.

## Gaps
- Which angle is yaw and which pitch ([L]; both rotate about perpendicular axes).
- Pellet loop breaks / ray-length reduction (`local_4ac -= distance`) after penetrating a first target: not ported.
- Random generator (`fn@0x41c480`) not analysed; the Rust takes any `rand(lo,hi)`.
