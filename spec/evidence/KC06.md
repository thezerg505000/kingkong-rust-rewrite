# KC06 Grab enemy
Main document for the grab state; KC07 (throw), KC08 (bite), KC14/KC15 (objects/creatures as weapons) point here.

## Behaviour (what the game does)
Grabbing is **proposal based**. Grabbable things (creatures, grab objects, mash objects) publish a proposal message of
type 0xc to Kong every frame from their own `*_exec_propose_grab` (weight = squared distance, plus bonuses; message
kind bit 1/2/4/8/0x40 says what Kong may do with it). In `k_ETAT_main` the attack button first polls the proposal list
(`fn@0x7dd5b0(0xc, slot, !carrying)`); a proposal with kind bit 8 sends Kong to `k_ETAT_grab@0x8dae10` (action id 0x15e)
instead of punching. In the grab state the *held thing drives the protocol*: Kong reads the message kind of the link
(`fn@0x6e2e70`) and plays the matching move; creatures answer with their own `*_ETAT_grabbed` states (V-Rex:
KC12/B02). While holding, Kong cannot take hits through the normal path in the grab action (`k_exec_detect_paf` ignores
kind 0x10000 grab hits) and the opponent table stays active. Nothing is grabbed when Kong is in fury (the proposal function
refuses, see below) except objects.

## Code
| address | name | role |
|---|---|---|
| 0x8dae10 | k_ETAT_grab | grab state, action id 0x15e, 25 KB; init at entry (`Kong+0x5c = 0x15e`, `Univers+0x6264 = 1` = Kong grab camera mode, `Kong+0x1ba0 = 10.0`); `fn@0x7dd3f0(0xd, ..)` polls mashing requests; `k_exec_detect_paf` |
| 0x8b5970 | k_exec_propose_grab (Kong as a proposer) | proposes Kong to a creature when: Kong has no object flag 0x400, (`Univers+0x1665c != 0` or [not fury and `Kong+0x1e80 == 0`]), the creature class is one of the grabbers (b99f64/b99f44/b99fa4) and `fn@0x606480(kong, creature) > 2`, Kong's action is not 1000/0x160/0x385/0x3e9 and `Kong+0x1af4 == 0` |
| 0x671c50 | KIGO_exec_propose_grab | grab objects: distance^2 < `KIGO+0x48` = 81.0 (radius 9); mask bit 4 only; weight 999+10000 (+200 if facing) |
| 0x4c8d70 | KIMO_exec_propose_grab | mashing objects: radius 11.0 (KC13) |
| 0x49ee50 | KT_exec_propose_grab | V-Rex offers itself (B02/KC11) |
| 0x8eb060 | k_exec_selection_grab | picks the best proposal by kind: kind 1/0x20/0x21/0xa1 nearest; kind 2 objects need distance^2 > 16 (25 for class b99f64); kind 8 needs distance > 12.0; kind 4 is never selected |
| 0x889e10 | (unnamed) `k_exec_grab_move_end(frame, cam, release)` | per message kind: kind 0x17 (60, -1, 0), 0x18 (78, 8, 0), 0x21 (50, -1, 1), 0x22 (78, `Kong+0x440`+9, 0), 0x23 (10, `Kong+0x440`+9, 1); at anim end releases (`fn@0x883540(held)`) when the flag is 1 |
| 0x8eaaa0 | k_TEST_Grab | the cancel-button probe |

Grab-state cases (`switch(fn@0x6e2e70(link))`): 1 (release at frame 0x3c), 2, 5 (carry / lift), 9, 0xe, 0xb, 0xc (anim of the held bone interpolated
by anim progress), 0xd, 0x10 (`Kong+0x1ba0 += dt * 150`), 0x14, 0x15/0x1f, 0x17, 0x18, 0x21, 0x22, 0x23. Kong's strike while holding a creature:
anim 0xa2 passing frame 0x12 once (`Kong+0x424`) sends `k_exec_hit_landed(2, 9, .., damage 10)` to the held creature (0x8db8d0..0x8dbae1,
second site 0x8e103f: class 2 damage 10).

## Data
Kong's move animations per message kind (ids in the Kong bank), the "kits" of each opponent (KC13), `KIGO+0x14` throw speed and `KIGO+0x18` damage (level instance data).

## Rust
`kong::combat::{Next::GrabState, GRAB_STRIKE, GRAB_STRIKE_ANIM, GRAB_STRIKE_FRAME, KIGO_PROPOSE_DIST_SQ}`; the grab choice is in `next_phase` (`grab_offered`).

## Gaps
Which creature species can be grabbed and which kind bits each publishes (needs the `*_exec_propose_grab` of KR, KBC, BC, crab, Scolo, KNa: the Kong-side
switch is mapped, the species table is not). Frame rate of anim frames.
