# A02 Patrol (raptor view; one species)
Main doc: `spec/evidence/X02.md`. The engine class `PNJ_Raptor_*` serves species 0xe (raptor), 0x10 (Jack-level V-Rex), 0x16 (compies); this is how the **raptor** (0xe) does it.

## Behaviour (what the game does)
`ETAT_VALA` (state 4, "va la") walks the raptor along the waypoint network of its territory (`exec_way_find_dest_pos@0x83ff10` path mode 1/2, `way_next_wp_get`, `way_move`), with `ai_perceived_seen = 1`, testing for targets and bites every frame; on arriving at the waypoint with a target present it returns to ATTENTE. Territory placement is done in `init` (`fn@0x470f20`, "n est pas sur un territoire" / "RAPTOR HORS TERRITOIRE" debug strings): a raptor must start on a territory waypoint cell.

## Code
`ETAT_VALA@0x8599f0`, `exec_way_*@0x83ff10/0x8464d0/0x85a120/0x865ae0`, `init@0x8315a0`.

## Numbers
| value | where | conf |
|---|---|---|
| ATTENTE -> VALA after 1.0 s idle without target | ATTENTE | C |
| waypoint wait timers (`+0x1fc0` f_use_current_wp_action_duration) are data | way_next_wp_get | L |
| walk speed = gait table `+0x215c[idx]`, smoothing factor 6*dt | select_action | C factor, speeds data |

## Data
Territory networks (waypoints, `ao_net_wp`) are level data: not available.

## Rust
`Raptor::step` state `Vala` moves toward `RaptorInput::patrol_dest`.

## Gaps
Path planning (Dijkstra over `ao_net_wp`) not ported; the Rust takes the next waypoint from the caller.
