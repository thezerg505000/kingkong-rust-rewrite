# N01 Player following (also covers N12 scripted waiting, N13 formation progression, NET_Follower, PLKJ)
## Behaviour (what the game does)
There is no separate "companion AI model". Ann, Hayes, Denham (and a 4th companion, slot 6) are extra instances of Jack's own `H_*` model:
`this+4` is the slot (1 Jack, 2 Ann, 3 Hayes, 5 Denham, 6 = Jimmy [L]) and `this[0] == 0` marks an AI-controlled one
(`H_exec_read_joy@0x579f30` reads pad buttons only when `this[0] != 0`; `fn@0x52f7b0@0x52f7b0` counts "companion wounded" for `this[0]==0` and slots 2,3,5,6) [C].
An AI companion idles in the follow state `H_ETAT_IA_suivi` (id 600). It walks along the level's waypoint network (`fn@0x437550` next-node search,
node flag 0x80 excluded, mask `G2+0x10b0`) towards the leader (the player, or `this+0x193c` when a script set one) and tries to stand at a
per-slot distance. Beyond 8 m of error it sprints. Orders (assist, heal, use, ammo, carry) arrive through the order queue `this+0x1180` and switch it out of the follow state
(`H_exec_change_etat@0x5c7df0`); when the order ends it returns to follow (`fn@0x43f2c0(2, state)` queued state).
## Code
- `H_ETAT_IA_suivi@0x57f1b0`: desired distance `local_70`:
  `this+0x1930` override (int, -1 = auto); `this+0x19cc` "hurry" flag (cleared when dist² to player < 16; if set and override 0 -> 5.0).
  Auto (-1): normal formation slot2 4.0, slot3 7.0, slot5 6.0, slot6 5.0; "tight" formation (when NOT [`this+0x1004 <= 0.6` or `this+0xaf8 <= 1.0` or `this+0xbf4 != 0` or `!elapsed(this+0x3d6c, 2.0)`])
  slot2 -5.5, slot3 3.0, slot5 -4.5, slot6 -4.5. With an override: override + {slot3 4.0, slot5 2.0, slot6 1.0}. `G2+0x10cc` (global rush) -> 15.0; inside a no-follow region
  (`fn@0x68a930`) or `this+0x3cc8 != 0` -> 100.0. If non-zero and the companion is moving (`this+0xc4c != 0`) +1.5.
  error = |desired - dist|; `error > 8.0` and not wading (`fn@0x689ff0`) -> sets run flag `this+0xbc0` [C].
- After 1.0 s in the state (`this+0xaf8 > 1.0`) it sets object flag 0x800 on itself: "available" [C]. `TrigCINE_WaitDisponibility@0x7664e0` returns 1 only when all (up to 5) listed actors have 0x800 [C].
- `NET_Follower*` @0x7809a0-0x781fe0 is a different, generic mover (used by scripted walkers, e.g. NPC groups): state `_wait` (arms when flag `this[1]` is set on `this[0]` or the player is within `this[2]` m; then counts down `this[3]` seconds -> `_run`), `_run` walks node to node on a network `this[4]`: speed `this+0x14` blended with `t=clamp(dt*this[7])` (-1 snaps), distance along the edge integrates `dt*speed`; at the node end picks the next node (`fn@0x437550`), end mode `this[9]`: 0 leave, 1 loop to start node `this[4]`; position mode `this[10]`: 0 smoothed corner curve with 0.33*edge-length handles, 1 straight; turn rate `this[6]` (-1 snaps) [C].
- `PLKJ_*` @0x448290-0x448850, 0x4d1080, 0x6bb1f0: NOT a companion system. `PLKJ_bhv_Play` reads `Pad_LeftStick_Deadzone`, `Pad_RightStick_Raw`, `Cam_GetMainObject` (`fn@0x76c0c0`) and plays random idle variations (`fn@0x76c730`, `Rand_Range`); `bhv_Init/Play/cine/beforemaintrack/aftermaintrack/after_blend` are Jade "behaviour" hooks and `PLKJ_headers/procs_ultra/misc/speech/IK/evolution/AI/timer` are empty library stubs sharing `AI2C_shared_stub_764990` with `Museum`, `Ragdoll_Lib`, `JoySimulate`. It is a stick-driven character behaviour package (museum/viewer-type); the acronym is not spelled out anywhere (strings are only the function names) [L].
- Scripting interface: cinematic messages 0x186a1..0x186a8 in `H_exec_ch_msg@0x5b3d70` (see N14).
