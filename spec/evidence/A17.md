# A17 Threat hierarchy
Main doc: `X04.md` (Jack V-Rex); raptor view `X02.md`.

## Behaviour (what the game does)
Every AI creature publishes a **beacon** each frame (`fn@0x6e3a70`, call it `Beacon_Create`; message type 1): `(class, flags, position, weight, life fraction)`. Other creatures read class (`fn@0x7dd2d0`), weight (`fn@0x6e44f0`) and life fraction (`fn@0x6e3c50`) from it. So "who is dangerous to whom" is not a table but the product of three things: (1) the **class** decides whether the observer needs line of sight (humans 1..12 do, everything else is always seen) and whether a bite grabs or strikes; (2) the **weight** is the score in the observer's weighted loop; (3) the observer's **priority chain** (forced > shot-me Jack > hurt-me > corpse > narrow cone > weight) overrides weights.
For the Jack V-Rex the effective order is: scripted cinematic target (flag 0x8000) > Jack once he has shot it (>10 damage) > any attacker 4 s after the last target change > nearest unclaimed carcass > Jack/creature in the 8 m narrow cone > highest weight inside the territory (raptors/creatures 150, Jack 100 or 200 with `+0x3d0`/attached, unknown 30, carcass 10).

Jack's published life fraction `fn@0x53ad10`: wound value 0 -> 1.0, 2 -> 0.3, 3 -> 0, otherwise (1.0) -> 0.15. Jack's category `mode*10 + sub` (sub 5 in state 0x2c0, 1 if flag `+0xb60`) lets the rex skip him when mode == 2 and sub == 1 (hiding) [C skip, hide meaning L].

## Gaps
The p10 argument (0.3-3.0, typically 0.4) and p12/p13 of `Beacon_Create` are stored but no reader was identified; weights of `BC_`/`KBC_` bats are computed at run time; the full class-id table (what class 2..12 are) is only partly known (Jack 1, other humans by player index).
