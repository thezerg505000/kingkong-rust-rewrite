## Behaviour (what the game does)
In Kong levels Ann is an AI actor of model `KAnn` (44 functions `KAnn_*@0x5edf10-0x601dc0`, one `TrigExec_KAnn_*` quartet, plus Kong-side `k_ETAT_grab_ANN`). She follows Kong along a follower network (`follow_network`) and switches to a scripted `action` state when a level script gives her a task (throw/fetch/light a javelin, hide, go to a point, act as bait). Kong picks her up with the grab button: `k_TEST_Grab@0x8eaaa0` sends Kong to `k_ETAT_grab_ANN@0x8bfc70` when Ann is the thing in reach (or already in hand). While held Ann sits in `grabbed_KK` (state 2) and is parented to Kong's hand; pressing grab again while carrying runs the same Kong state in its put-down branch and Ann returns to `follow_network`. Whether she is carried in the hand or on the shoulder is a level flag (`TrigExec_KAnn_On_Shoulder_Set`). Any accepted hit kills her (`paf` then `mort`); bats can carry her off (`grabbed_bat`), the V-Rex bites her (`grabbed_trex`).

### Pick-up (AN01)
1. Ann offers herself: `KAnn_exec_PROPOSE_KKGrab_Object@0x5f59a0` proposes her with weight 0.001 when she does not have flag 8, `|dz| <= 5.0`, horizontal `d^2 < 49` (7 m) and Kong is not "doing 0xb" (`Kong_IsDoing`) unless Ann herself is in `action` [C]. `k_exec_selection_grab@0x8eb060` keeps the proposal with the smallest metric, so 0.001 beats any other object [L].
2. Grab pressed (`Kong+0x7c` or `Kong+0x1ad8`): `k_TEST_Grab` first asks for a finisher target (query kind 0xc, bit 8 -> `k_ETAT_finish`), then, if Kong carries nothing (`+4 == 0 && +0x318 == 0`) -> `k_ETAT_grab` (normal grab), else (carrying) and the target object lacks flag 0x20 -> `k_ETAT_grab_ANN` [C].
3. `k_reflex@0x8a4360` l.255-300: a pending Ann request (`Kong+0x1a64 != 0` with `Kong+0x18c4` = Ann) runs the grab-object query (`fn@0x7dd5b0(4, +0x2b4, 1, grab_object_param, 0, grab_object_init)`), stores the handle in `Kong+0x318`, and sets `+0x37c = 1`. If `Univers+0x890c == 0` (hand mode) it sets `Kong+4 = 1`, `+8 = 1`, `+0xc = +0x368` (hand index), query mode 3 with bone 0x14 (hand) or 0x28; otherwise (shoulder mode) mode 5 with clip 0xd3. [C branches, hand/shoulder naming L]
4. `k_ETAT_grab_ANN` (Kong state 0x15f, entry writes `Kong+0x5c = 0x15f`): if Ann is not yet carried it plays Kong clip 0xa8 (reach) and stores the direction to Ann in `+0xd20`; the 'already carried' variant plays 0xaa; the timer `Kong+0x68` drives the sequence: `> 0.55` s mode-2 hold, `> 1.15` s hand mode closes (`mode 3`), `> 1.95` s shoulder mode releases (`mode 5`, clip 0xd3) [C thresholds, roles L]. Kong holds one of two Ann ride states depending on `+0x368` (bone 0x14 / 0x28).
5. Ann side: the query result `fn@0x6e2e50(+0x8c)` (hand category) is mirrored in `Ann+0x20c`; `grabbed_KK` is entered when the engine reassigns her slot 2 state to it. On entry (`+0x248 != 2`) it zeroes the 14 server slots `+0xe0..+0x114`, sets `+0xe4 = 1`, `+0x108 = 1`, `+0xf0 = 1`, parents Ann to Kong's hand actor (`fn@0x43fce0(Ann, handActor, 3, set_pos_callback)`), zeroes velocity and acceleration, plays anim 0x1d (unless already 0xdc), and sets Kong's cache `fn@0x5eeff0(0)`. [C]
