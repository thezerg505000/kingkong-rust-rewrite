# E09 Door mechanisms (rotating posts / cranks)
## Behaviour
`Interactive_Door` (`InteractiveDoor_init@0x874c30`, `_loop@0x876330`, `_update@0x875be0`, `_waitactivation@0x878180`, speech `_exec_speech@0x877df0`) is a door whose opening ratio `this[0x10f]` (0..1) slides/rotates it between closed and the `mo_OpeningWP` target (`InteractiveDoor_update`: position lerp from the door's own position to the waypoint, and rotation lerp of its axes by the same ratio). Door types (`this[0]`): 0 plain (opened by a script test only), 1 "porte denham" (removed: init logs "plus de porte denham (AI stop)"), 2 pillar door.
A pillar door has 1 or 2 pillars (`this[0x99]`, init aborts otherwise: "not enough or too much pilar (pilar nb = 1 or 2)"), each pillar with a socket for a lever ("pilar levier"). The door opens (a) when its `mt_OpeningTest` script test is true, or (b) when its pillars are turned by operators. Jack turns a pillar by walking up (prompt id 9 within 2 m: `Obj_DistSq < 4.0`), pressing interact (lever flag 0x8000 -> `player+0x3440 = pillar`, `+0x3444 = lever`, `+0x3448 = 0.576`), then holding action button 7 after the first second in `H_ETAT_Ia_porte` (0x268) and pushing the stick along the pillar axis (rotation `rate * dt`, rate 0.576 rad/s [L unit], sign flipped for mirrored pillars, flag 0x20) while the pillar flag 0x4000 is set by the door. Companions are assigned as operators (E11) and turn with `H_ETAT_IA_use` (0x261) kind 5 at the same rate.
When the door is open and has pillars, the pillar prompts stay (`fn@0x48da30`) so they can be turned back; the "needs two" speech plays once (cue 3) when the pillar lever count is not satisfied.
## Code
- `fn@0x48d940@0x48d940` (named `InteractiveDoor_exec_timing`): opening time `this+0x228`, closing time `this+0x22c`; negative -> 0.1 s; closing time is divided by 3.0; crank rate `this+0x42c = 0.576` [C]. `TrigExec_Door_SetOpeningTime@0x804270` rewrites the opening time at run time and flags the door (0x2000) so the timing is recomputed [C].
- Loop end: if not (open test || flag 0x200): close at `dt / closeTime` (never when closeTime >= 10000; frozen when negative); else opening: `dt / openTime` unless flag 0x400 (hold) is set, instantly when openTime < 0 [C]. Flags 0x20/0x40/0x80 are set on the door while opening/closing/steady and drive door sounds (anim 0/3/5 etc., `fn@0x427ea0` sound slots 1 and 4).
- Persistence: init asks `fn@0x440500(self, 0, 0xc9, 0x5dc)` for a save id and `fn@0x432f10(G+0xc08, id)`; an already-open door is rebuilt open via tagon/update/tagoff [C].
- Navigation tag: `InteractiveDoor_callback_tagon/tagoff` cut and restore a navigation-network tag (`fn@0x427b90(+-0x10)`, size `this+0x258/0x25c`) so AI paths avoid closed doors; edges between `this+0x454` and `this+0x458` toggled with flag 0x80 on the global network `G2+0x10c8` [C].
