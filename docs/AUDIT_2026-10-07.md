## Ruling 1: 0x38d1b717 is a float (1e-4), not a message id

**Ruling: the float 1.0e-4. It is the lifetime in seconds of a message-queue record. KC01.md/KF01.md ("hit message id") are wrong. H02.md does not
mention the constant; the "delay argument" reading is in C10.md and is right, with the refinement that the field is a time-to-live.**

Evidence:
1. Bit pattern: 0x38d1b717 = 1.0e-4 as IEEE-754. `.rdata` 0xaf5500 holds `17 b7 d1 38` and is the epsilon of `MATH_IsZero@0x41d450` (the same constant `fury.rs` already uses).
2. Argument position. All senders funnel into `fn@0x43b580(sender, queue, word1, template, flags, out)` @0x43b580, which does `rec[1] = param_3` and `rec[2] = param_1`.
   - `Msg_SendJackScreenFx@0x6e5060`: `fn@0x43b580(DAT_00b420e4, 0x16, 0x38d1b717, ..)`.
   - `fn@0x6e4680@0x6e4680` (the fury-shout stimulus; sole caller `k_exec_fury_start@0x883430` line 39): its `param_3` goes to `fn@0x43b580(param_2, 0x14, param_3, ..)`; the call passes 0x38d1b717 as `param_3`.
   - `Msg_BuildHit@0x6e3e70` line 128 `fn@0x43b580(param_4, 4, param_5, ..)` and `Msg_SendPaf@0x6e3df0`: `fn@0x43b580(param_4, 4, param_5, ..)`; every caller passes `(.., DAT_00b420e4, 0x38d1b717, ..)` in the (param_4, param_5) slots (e.g. `k_exec_melee_hit` line 330, `PNJ_Raptor_exec_bite` line 355, `PNJ_Scolo_Reflex` line 358).
3. Consumer. `fn@0x43b360@0x43b360` (per-frame queue aging, lines 21-22): `rec[1] = rec[1] - DAT_012f797c; if (rec[1] <= 0) rec[0] |= 2` and the record is then freed (`rec[1]` is reused as the free-list link). Flag bit 8 (`param_5 & 8` in 0x43b580) skips the aging. So `rec[1]` is a float TTL, here 1e-4 s = "expires on the next tick".
4. Matching never uses it. `fn@0x43bd70@0x43bd70` (the query used by every `check_paf`, `Stimulus_Paf`) compares only template words [0..5] against `rec[2..7]` and extras `[0x15..0x19]` against `rec[0x17..0x1b]`; word `rec[1]` is not tested. The kind of message is the queue index (`param_2` of 0x43b580): 4 = hit/paf, 0x14 = stimulus (fury shout), 0x16 = Jack screen FX, 0x13 = speech.
5. The same constant family is used all over as a plain float: `fn@0x43c590(0x38d1b717)` (pushes a float; other callers pass 0.5, 0.1, 0.01, 1.0, 3.0), `fn@0x408cb0(.., 0x32ca, 0x38d1b717)`, `fn@0x6994b0(.., 0x38d1b717)`, `fn@0x9b4530` line 24 (`0x38d1b717 < ABS(..)`, an epsilon compare). Sibling constants in the same slot elsewhere: 0x3a83126f (0.001, `Msg_CreateBeacon` and the AN01 proposal weights).

Other docs that still describe it as an id (cross-note added, bodies not rewritten): G07, J14 ("id 0x38d1b717 ... Receiver not located": there is no receiver of an id, it is the TTL), N02 ("message type 0x13 id 0x38d1b717"), S06, S07, W06; E13 ("1e-4 key").
